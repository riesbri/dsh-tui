# Bilingual documentation

dshline's documentation is maintained in English and Simplified Chinese. Its readers are
DeepSeek Harness users, and Harness itself is a bilingual project — a terminal frontend whose
whole pitch is that it presents Harness capabilities should be readable by the same people who
read Harness.

This page defines the pairing contract and the local terminology decisions.
[`tools/verify-translation-pairing.mjs`](../tools/verify-translation-pairing.mjs) enforces the
mechanical half of it; the rest is the reviewer's.

## The pairing contract

- **A pair is three sibling files.** The English `foo.md`, the Chinese `foo.zh.md`, and a
  consistency record `foo.i18n.yaml`, all in the same directory. No locale directories, no
  separate translation repository, no interleaved bilingual files.
- **Pairs merge whole.** A pull request never lands one language without the other two files.
- **Both sides carry equal authority.** A document may be authored in either language and the
  counterpart translated from it. What binds them is that they must say the same thing.
- **The consistency record** holds the git blob hash of each side as of the last time the two
  were confirmed consistent:

  ```yaml
  README.md: 3f786850e387550fdab836ed7e6dc881de23001b
  README.zh.md: 89e6c98d92887913cadf06b2adb97f26cde4849b
  ```

  Blob hashes rather than commit hashes, so the record is computable for files edited in the
  same pull request and consistency is a pure content comparison.
- **Language switcher.** The Chinese file links back immediately after its H1 with
  `[English](foo.md) | 中文`; the English file reciprocates there with
  `English | [中文](foo.zh.md)`.
- **Structure mirrors the counterpart.** Heading depths and order, code fences (info string and
  body, byte for byte), table row and column counts, list kinds, ordered-list starts, and item
  counts match one to one.
- **Links stay in their own locale.** Where a relative link targets a document that is itself in
  scope, the English side uses its `.md` path and the Chinese side its `.zh.md` path — otherwise
  a reader who follows one link out of the Chinese docs never finds a way back in.

## The gate

```sh
pnpm run verify-docs                 # the corpus check CI runs
pnpm run verify-docs --list          # every pair's state: ok, out-of-sync, invalid, missing
pnpm run verify-docs docs/usage.md   # just this pair, for a fast edit loop
pnpm run verify-docs --write docs/usage.md   # re-record a pair you confirmed
```

`--write` requires naming the pairs. That is deliberate: the yaml diff **is** the reviewable act
of confirming that two documents say the same thing, so a blanket re-record would let an
unreviewed translation through wearing a green check.

The practical rule this creates: **when a pull request edits either side of a paired document,
the same pull request updates the counterpart and re-records the pair.** A pull request that
leaves a pair out of sync goes red in CI.

Update a counterpart by patching it minimally against the edited side's diff, never by
re-translating the whole file. Re-translation discards reviewed wording, and reviewed wording is
the expensive part.

**The gate's limit, stated plainly:** a green gate means the pair was confirmed consistent at
these exact contents, not that the confirmation was sound. It checks hashes and Markdown
structure. Whether the two sides actually say the same thing, in the right terminology, is the
reviewer's half of the contract.

## Scope

**In scope:** `README.md`, `ROADMAP.md`, `CONTRIBUTING.md`, `SECURITY.md`, and every `docs/*.md`.

**Excluded**, and the gate rejects a `.zh.md` or `.i18n.yaml` for them:

- `AGENTS.md` — agent instructions, maintained in English only, as upstream keeps its own.
- `CHANGELOG.md` — generated by Changesets; a translated copy would be overwritten by the next
  release.
- `docs/i18n.md` — this page; it quotes both languages by construction.

### Documents awaiting a counterpart

A document that is in scope but not yet translated is listed in `PENDING` in
[the gate](../tools/verify-translation-pairing.mjs). The gate reports it on every run and does
not fail; a document **not** on that list must be a complete pair. A half-built pair — one file
without its record — always fails, pending or not, because that is exactly the state that
produced the drift this gate exists to prevent.

Deleting the last entry is the point. Nothing should be added to the list without saying why in
the pull request that adds it.

`packages/*/README.md` are not yet in scope. They are short and npm-facing; they can join once
the root corpus is stable.

## Terminology

The source of truth is upstream Harness's
[`docs/i18n/terminology.md`](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/i18n/terminology.md).
Read it before translating. dshline follows it rather than maintaining a rival glossary, because
a reader moving between the two projects should not have to relearn the vocabulary.

The terms that come up most in these documents, and that a first-pass translation reliably gets
wrong:

| English | Chinese | Note |
| --- | --- | --- |
| agent | `agent` | Stays English. First occurrence `agent（智能体）`; never bare `智能体`. |
| subagent | `subagent` | Stays English; never `子代理`. |
| seam | `seam` | Stays English. Explicitly **不要译作** `接缝`. |
| slot | `slot` | Stays English; never `坑位`. |
| provider | `提供方` | Translated. `provider-neutral` → `提供方无关`. |
| contract | `约定` | Not `契约`. |
| capability | `能力` | Must stay distinct from `feature` → `功能`. |
| background job | `后台任务` | `job id` stays English. |
| transcript | `文本记录` | First occurrence `transcript（文本记录）`. |
| compaction | `压缩（compaction）` | |
| consumer | `消费方` | Not `消费者`. |
| artifact | `产物` | Not `制品`. |

Two decisions dshline makes that upstream's table does not cover:

- **`scrollback` → `滚动缓冲区`.** Not `回滚缓冲区`: `回滚` reads as *rollback*, which is the
  opposite of the guarantee. Native scrollback is this project's central claim, so the word for
  it has to be right.
- **`secret` / `secrets` → `密钥` or `机密`, by context.** Not `密文`, which means *ciphertext*.
  dshline never holds a credential value at all, so a word implying it holds an encrypted one is
  wrong twice.

**`Harness` is always capitalized in Chinese, even where English writes `harness`.**
English distinguishes the product (`Harness owns capabilities`, `a Harness profile`) from
the running thing (`the harness's own launcher`, `the harness gives the model a tool`) with
an article. Chinese has no article, so the two collapse to one token and the distinction is
unrepresentable — which leaves the product name as the only honest reading. This is not an
inconsistency to fix on the English side; the English casing is deliberate.

**Prefer the term Chinese technical writing already uses over a word-for-word calque.** The
translation this corpus started from had several: `旗标` for a command-line flag (`命令行选项`),
`包装` for a software wrapper (`封装`), `手工` for editing something by hand (`手动`), and
`挺过退出` for a session surviving a quit. Each was understandable and each read as translated
rather than written. A sentence that has to be decoded back into English before it makes sense
has not been translated yet.

Code fences are verbatim on both sides, **including their comments**. A command line is what
people copy, and a comment that exists in only one language is drift the gate cannot check.
Explain the command in the prose around the fence instead.
